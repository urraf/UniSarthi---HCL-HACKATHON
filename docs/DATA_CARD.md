# Synthetic Data Card (Annex E)

Built in the team data repo [anish295/HCL-Database](https://github.com/anish295/HCL-Database) and copied here: CSVs in `backend/data/students/`, prompts in `backend/data/prompts/generation_prompts.md`, generator `backend/scripts/generate_students.py`, validator `backend/scripts/validate_data.py`, schema `backend/data/team_schema.sql`.

**Added in this repo:** `scripts/fill_attendance.py` (seeded) gives every student an attendance row in each course they have a result for (70 rows, 128 in total), so every student can ask about attendance. DETAINED results get attendance below the 60% floor, all others 78-96%; the hand-placed edge-case rows are kept unchanged. Validator: PASSED, 0 violations.

| Field | Content |
|---|---|
| **Purpose** | Exercise every question type in the guide (policy fact, procedure, personal data, personal eligibility, multi-step/what-if, refusal) against NSUT's real rules, including threshold edge cases. All persons are fictitious. |
| **Generator** | Claude (claude-sonnet-5-5 and claude-opus-5-5) in Claude Code wrote `scripts/generate_students.py`; the rows come from that seeded script (`random.seed(20261006)`), so output is reproducible. ~1 generation run per iteration, no free-text LLM row generation. |
| **Prompts** | `data/prompts/generation_prompts.md` |
| **Schema enforcement** | `scripts/schema.sql` (CHECK constraints, FKs) + `scripts/validate_data.py` (types, ranges, FK, PK, attended<=held, total=internal+external, result consistent with marks using thresholds read from `rule_registry.csv`, roll-number format, backlog consistency). `load_students.py` refuses to load if validation fails. |
| **Row counts** | 32 students (S1001-S1032); 4 cohorts x 8: B.Tech IT 2023, B.Tech IT 2024, B.Tech CSE 2023, B.Tech CSE 2024. 10 courses, 58 attendance rows, 85 results rows. 2023 batch is in semester 7, 2024 batch in semester 5 (as of 2026-10-06). |
| **Distributions** | Normal students: CGPA uniform 6.2-9.4; attendance 80-97%; passing marks internal 26-48 + external 22-48 (out of 50 + 50). Edge-case students are hand-placed. |
| **Edge cases** | See `edge_cases.csv` (25 students). Exactly 75% attendance: S1002, S1009, S1018, S1021, S1025. One class below (72.5%): S1003, S1010, S1026. Exactly 60% floor: S1004, S1011, S1027. Below the 60% floor: S1012 (58.5%), S1022 (50%). Fail at 34 (one under 35): S1002, S1013, S1018, S1028. ESE 14/50 (<30%) with total 55: S1006. ABSENT: S1003, S1014, S1022, S1029. DETAINED: S1004, S1019. Multiple backlogs: S1004 (4), S1016 (3), S1022 (5), S1032 (3). Supplementary cleared: S1006, S1013, S1029; supplementary failed/absent: S1014, S1028. CGPA exactly 8.50: S1001, S1020; 8.00: S1009, S1025; 7.50: S1005, S1021 (S1012 also, by chance); 6.50: S1008, S1028; 5.00: S1004, S1022. |
| **Validation results** | `validation_report.txt`: PASSED, 0 violations. Negative test: 6 deliberately corrupted rows were all caught (11 violations incl. knock-on errors). |
| **What the LLM got wrong** | (1) Misdated a corpus document (notice-board posting date 9-Sep-2025 vs the printed date 7-Jul-2025) - caught by reading the scan, register corrected. (2) A wrong edge-case note for S1028 (described the supplementary marks incorrectly) - fixed. (3) A dead branch in the ID check that would have blocked judges' S9xxx IDs - removed. |
| **Known limitations** | (a) "Placement CGPA cut-off": the 2024-25 T&P policy has NO university-wide cut-off, so CGPA edge cases use degree/division/honours/scholarship thresholds instead. (b) Credits are assumed 4 per course (Regs-2019 Cl. 6.8); no collected document prints NEP credits. (c) Grades use the absolute scale (Table 5) although NSUT uses relative grading for classes >30. (d) Schema's `SUPPLEMENTARY` exam type exists although Regs Cl. 12.3 says there are none (modified in practice by Exam-Only Mode/make-up circulars) - a deliberate conflict for the assistant to explain. (e) CGPA is not recomputed from results. (f) 2023-batch attendance rows exist only for Study-Mode re-registrations; sem-7 courses are not modelled. (g) Roll numbers follow the real format but are fabricated and may coincide with real people's numbers; names are random combinations. |
